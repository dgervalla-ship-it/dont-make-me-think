# Arbitrages — quand les sources tirent dans des sens différents

> Charger dès qu'une décision oppose deux règles. Chaque arbitrage dit **dans quel contexte**
> chaque approche convient ; aucun ne donne une règle absolue. Les critères de choix sont des
> **déductions** documentées, sauf mention.

| # | Tension | Approche A (contexte où elle convient) | Approche B (contexte où elle convient) | Critère de choix | Sources |
|---|---|---|---|---|---|
| T1 | Navigation partout vs navigation réduite | Barre globale sur chaque écran : zones de **consultation**, allers-retours fréquents entre rubriques | Navigation réduite + sortie nommée : **parcours engageant** (paiement, assistant, formulaire long) où quitter a un coût | L'écran est-il une étape d'un engagement en cours ? | DI ch.3 p.137, 141 (PDF 157, 161) ; DMMT ch.6 p.67 (PDF 78) |
| T2 | Accès direct (peu de gestes) vs choix sans effort | Réduire les gestes : tâche **répétée** plusieurs fois par jour/semaine par un utilisateur habitué (saisie en série par un opérateur, relance comptable) | Ajouter une étape claire plutôt qu'un choix ambigu : tâche **rare** ou utilisateur **novice**, incertitude ressentie | Répétition × incertitude : répétée et comprise → raccourcir ; rare ou ambiguë → clarifier. Pas de règle des « trois clics » | DI ch.2 p.33–34, ch.3 p.133–135 (PDF 53–54, 153–155) ; DMMT ch.4 p.43–47 (PDF 54–58) |
| T3 | Tout montrer vs divulgation progressive | Sections titrées tout visibles : écran de décision, informations comparées, peu de contenu | Accordéons/onglets/activation progressive : options secondaires, contenu long, experts | L'information conditionne-t-elle la décision de l'écran ? Si oui : visible | DI ch.4 p.224–250 (PDF 244–270) ; DMMT ch.10 p.147–149 (PDF 158–160) |
| T4 | Confirmation vs habituation | Confirmation spécifique : action **rare et irréversible** (argent, suppression, envoi à un tiers) | Pas de confirmation + annulation possible : action **fréquente et réversible** | Fréquence × réversibilité ; une confirmation fréquente devient un clic réflexe | DI ch.1 p.18–19 (PDF 38–39), ch.8 p.404–421 (PDF 424–441)  |
| T5 | Assistant vs formulaire unique | Assistant : tâche **nouvelle**, longue, ramifiée (onboarding, première réservation guidée) | Formulaire court : tâche **répétée** par un expert, peu de champs | Fréquence pour ce rôle + nombre de branches | DI ch.2 p.86–89 (PDF 106–109) |
| T6 | Accueil : accès direct vs tableau de bord vs points d'entrée | Accès direct : une question domine (client : prochaine échéance ou prochain rendez-vous) | Tableau de bord : surveillance continue (back-office, direction) ; points d'entrée : novices, usages variés | Rôle + question dominante **observée** (sinon hypothèse à tester) | DI ch.2 p.51–52, 78–81 (PDF 71–72, 98–101), ch.3 p.143–147 (PDF 163–167) ; DMMT ch.7 |
| T7 | Conventions des livres vs conventions actuelles | Utilitaires « en haut à droite », logo « en haut à gauche » : web bureau | Conventions de plateforme mobile, shell existant du produit | Les conventions **du projet** (design system) priment (C-04) ; celles des livres sont datées (2014–2020) | DI ch.3 p.185–188 (PDF 205–208) ; DMMT ch.6 |
| T8 | Organisation par tâches vs par audience | Par tâches : navigation d'un espace | Par audience : **séparation des espaces** (ex. back-office, espace client, console admin) déjà imposée par les rôles authentifiés | Hors connexion (portes d'entrée, site public) : l'auto-sélection d'audience coûte ; après connexion : le rôle est connu, organiser par tâches | EIA ch.3 p.39–40 (PDF 45–46) |
| T9 | Fil d'Ariane | Hiérarchie ≥ 3 niveaux, arrivées en profondeur (back-office : réglages, fiche client › onglet) | Titre + retour : hiérarchie courte, mobile | Profondeur réelle + largeur d'écran | EIA ch.5 p.82–83 (PDF 88–89) ; DMMT ch.6 p.79–80 (PDF 90–91) ; DI ch.3 p.193–198 (PDF 213–218) |
| T10 | Indicateur de chargement | Indicateur de progression : opération longue, mesurable | Contenu partiel / skeleton : chargement de page (si le design system du projet le prescrit : pas de spinner plein écran) | Durée et nature de l'attente | DI ch.8 p.409–414 (PDF 429–434) ; règles UI du projet |
| T11 | « Premier choix plausible » vs actions coûteuses | Laisser deviner et corriger : navigation, consultation | Récapitulatif + libellé explicite : engagement (réservation payante, annulation, facture) | Coût d'une erreur de premier clic | DMMT ch.2 p.24–25 (PDF 35–36) ; DI ch.8 p.404–408 (PDF 424–428) |
| T12 | Cohérence vs clarté | Cohérence entre espaces : mêmes objets, mêmes libellés, mêmes gestes | Écart local assumé : si nettement plus clair pour un rôle donné, écrit et testé | Gain de clarté démontré > coût de l'incohérence | DMMT ch.3 p.31–33 (PDF 42–44) |
| T13 | Recherche partout vs nulle part | Recherche : listes longues, re-recherche fréquente (back-office : clients, factures ; console admin : comptes) | Pas de recherche : espace petit et bien organisé (espace client simple) | Volume + mode de recherche d'information (A-13) ; ne pas l'ajouter mécaniquement | DMMT ch.6 p.71–72 (PDF 82–83) ; EIA ch.5 p.89–94 (PDF 95–100) |

## Comment consigner un arbitrage
Dans la décision UX (`templates/decision-ux.md`) : nommer la tension (T-n), le contexte réel (rôle, fréquence observée ou supposée, réversibilité), le choix, et **ce qui ferait changer d'avis** (résultat de test, donnée d'usage).
